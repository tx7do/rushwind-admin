# 三端前端：同步快照语义与验收

本仓**不写前端页面代码**。`frontend/admin/{react,vue-element,vue-vben}/` 是上游前端的三份字节冻结同步快照，页面开发发生在上游契约源一侧，本仓只负责：同步、品牌覆写、菜单 seed、验收。这份参考讲清楚快照的机制边界，以及新模块页面的正确时序。

## 快照构成

```
上游三端整树 ──sync-frontend.sh──▶ frontend/admin/<前端>/     字节冻结（.gitattributes -text）
                    │
                    └─ 自动施加 brand/apply-brand.sh          RushWind 品牌覆写层
                                                               （唯一允许的对上游偏离）
```

- 双清单门：`frontend/admin/<前端>.MANIFEST.sha256`（防手改，`--check` 不一致 exit 1）+ `<前端>.UPSTREAM.sha256`（上游漂移基线，源仓在时漂移 exit 2）。
- `export LC_ALL=C` 钉排序（UTF-8 collation 会让清单换位必红）。
- git log 里前端目录只应出现 sync/品牌类提交——任何功能 diff 都是错位。

## generated TS 的来历

`src/api/generated/admin/service/v1/index.ts`（头部 `// Code generated by protoc-gen-typescript-http. DO NOT EDIT.`）**随快照同步进来**，三份字节相同、与后端 vendored protos 同 vintage 对齐。**本仓没有任何 TS 重生成命令**——上游演进后重同步时，三端快照 + 后端 protos 在同一上游提交一次性接受。要改 generated 类型 = 改上游 proto，回到 `references/backend.md` Step 1 的契约流。

## 新模块页面的正确时序

```
1. 上游契约源侧：proto（回到本仓同步）+ 页面实现 + generated TS 重新生成
2. 本仓三端重同步（见下）——快照带来页面与 generated TS
3. 本仓菜单 seed 行（backend.md Step 11：seed/menu_data.rs，parent 在前；
   component 指向快照内的页面路径）
4. 三绿验收（见下节）
```

三端各自的列表/表单/刷新机制差异（ProTable+invalidateQueries / ProPage+refresh() / VxeGrid+gridApi.reload() 等）属于上游一侧的实现知识，不在本仓维护——改页面回上游，别在本仓快照里动手。

## 同步命令

```bash
# Linux 上默认源是 Windows 路径，必须 env 覆盖；本机克隆在 ~/Github/go-wind-admin 时：
REACT_FRONTEND_SRC="$HOME/Github/go-wind-admin/frontend/admin/react" \
  bash frontend/admin/sync-frontend.sh react            # 同步 + 自动品牌覆写 + 重建两份清单

bash frontend/admin/sync-frontend.sh react --check      # CI 门（三端各一）
```

env 变量名规则：`<大写前端名>_FRONTEND_SRC`（`REACT_FRONTEND_SRC` / `VUE_ELEMENT_FRONTEND_SRC` / `VUE_VBEN_FRONTEND_SRC`）。sync 会整树覆盖 + 重建 `MANIFEST.sha256` 与 `UPSTREAM.sha256` 两份清单。

## 三绿验收（development-plan Phase 3 的模块合并门槛）

新模块声明完成 = 三项全过：

1. **模块端点差分 100% 一致**：`cargo run -p admin-diff -- --go http://127.0.0.1:27788 --rust http://127.0.0.1:7788`（语料/豁免/输出见 `backend/testbed/README.md`）。**未经用户明确允许不得启动/触碰 docker 差分栈**——红线。
2. **矩阵全绿**：backend.md Step 12 的六门序列。
3. **前端页面冒烟**：快照内 dev server 起来后（各端自己的包管理脚本），登录走查新菜单页的 list/搜索/分页/表单——页面代码本身来自上游快照，此处验证的是**菜单 seed 行、component 路径、i18n 标题在本仓侧接对了**。

## 禁手改清单

- `frontend/admin/{react,vue-element,vue-vben}/` 快照树内的一切（双清单门盯着）。
- 两份 `.sha256` 清单（只由 sync 脚本重建）。
- 品牌偏离只进 `frontend/admin/brand/`（`overlay/<前端>/` + `tools/` + `apply-brand.sh`），不直接改快照文件。
